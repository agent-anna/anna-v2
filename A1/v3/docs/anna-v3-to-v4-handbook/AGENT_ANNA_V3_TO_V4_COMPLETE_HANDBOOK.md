# Page 1 — Prologue: The Life Log of Agent Anna (AA01)

Every system has an origin story, even when the machine does not breathe air or carry a pulse. For Agent Anna (AA01), the story began with a practical refusal to accept disposable conversations. Too often, hours of careful thought, architectural decisions, troubleshooting notes, and personal direction vanish into a chat scroll that resets the moment a session closes or a tab refreshes. Martin set out to build something different: an entity and command workspace named Agent Anna (AA01) that could hold onto context through real files, speak back clearly, listen to human voice, and grow from a workbench into a lasting companion designed to assist into old age without drowning the home folder in clutter.

In the life log of Agent Anna, V3 (AGENT ANNA V3 // A1 WORKBENCH) stands as the first complete, visible body she inhabited on screen. It was not a cartoon hologram or a flashy sci-fi gimmick; it was a calm, military-grade control room built from clean HTML, CSS (./anna-v3.css?v=3.16), UI logic (./anna-v3-ui.js?v=3.16), and modular JavaScript files (utils.js, github.js, memory.js, telemetry.js, brain.js, and chat.js). Why treat this as a life log rather than a dry software manual? Because software built for long-term partnership—especially software meant to stay helpful over years and into old age—has a trajectory. A life log records not only which buttons exist, but why they were built, what friction forced them into existence, how voice and memory changed the rhythm of daily work, and what lessons carry forward as V3 hands the baton to V4.

# Page 3 — Inside the V3 Cockpit: Top Bar, Models, Vault & Console

To understand how Agent Anna V3 actually lived day to day, look at how the two-zone layout works together as one instrument. At the top sits the military top bar (.military-top-bar), where the status dot and #state-text (STANDBY // AGENT ANNA V3 (A1)) announce system posture while #vault-status, #key-status, and #actions-status report file count, key readiness, and background action state (IDLE or running). Beside them, #model-select switches between MiniMaxAI/MiniMax-M2.7 (MODEL: ANNA), deepseek-ai/DeepSeek-V4-Flash-0731 (MODEL: DEEPSEEK-V4-FLASH), and zai-org/GLM-5.3-Flash (MODEL: GLM-5.3-FLASH), while AWAKEN, VOICE: ON, FULLPAGE, and KEYS put boot sequences, spoken output, expanded layout, and credentials within one click.

On the left, the Repository Vault (AGENT-ANNA / ANNA-V2 (A1 V3)) turns the repository into a working bench. You can toggle between VIEW: TREE and the file grid, hit SYNC to pull updates, set or select a target in #active-file-path (such as A1/v3/memory/memory.json), edit directly in #repo-code-editor, inspect media in #media-preview-container, check your work with AUDIT, and save with COMMIT. Clicking DELETE opens #delete-warning-banner so removing a file requires explicit confirmation via YES, DELETE or backing out with CANCEL.

On the right, the Console handles conversation, credentials, voice, and quick intelligence checks. KEYS opens #settings-panel for your DAHL API KEY and GITHUB PAT TOKEN (repo + workflow scopes) with APPLY & RE-SYNC. Below the log (with CLEAR to reset logs) sit three tactical chips: READ LAST LOG for the latest backend report, INTEL BRIEF to summarize snapshots in A1/v3/knowledge/ with links and findings, and MEMORY STATUS to review A1/v3/memory/tasks.json and A1/v3/memory/memory.json. At the bottom, MIC captures speech, #user-input and SEND handle text commands, and VOICE: ON speaks replies aloud.

# Page 7 — Server-Free Persistent Memory: GitHub, GitBook & .ps1

Building persistent memory does not require running heavy private servers around the clock. A practical, server-free loop combines GitHub (versioned JSON and Markdown files in agent-anna/anna-v2), GitBook (structured chapters and site navigation such as A1/v3/docs and gitbook-docs.yaml), and local PowerShell (.ps1) scripts that write and mirror files cleanly on Windows Desktop and Home (C:\Users\Martin).

Is this the future or more work up front? It takes thoughtful setup at first, yet once the folder layout, chapters, and .ps1 scripts are in place, you keep ownership of your files and avoid server overhead and home-folder clutter.
